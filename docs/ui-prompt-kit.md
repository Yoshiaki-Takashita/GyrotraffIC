# UI の質を上げるためのプロンプト集（GyrotraffIC 用）

公開されている資料の考え方を組み合わせた、UI 担当への指示の型。全文の転載はせず、要点と出典だけを書く。
資料の確認の程度：Anthropic の公式の記事は検索結果の抜粋のみ（全文は未確認）。Stitch の記事はコミュニティの投稿（公式文書ではない）。

## 出典
- Anthropic「Prompting for frontend aesthetics」（公式のクックブック）：https://platform.claude.com/cookbook/coding-prompting-for-frontend-aesthetics
- Anthropic の frontend-design スキル（公式のリポジトリ。美的な方向を先に決めてから書く）：https://x-cmd.com/skill/anthropics/frontend-design に概要
- Google Stitch のプロンプトの型（コミュニティ）：https://discuss.ai.google.dev/t/stitch-prompt-guide/83844

## 型 1：Anthropic の「ありきたりを避ける」型
1. 設計の次元に名前を付けて指示する：書体・色とテーマ・動き・背景と奥行き・配置と余白。
2. 参考にする文化や美学を具体的に挙げる（「きれいに」だけでは、無難な既定値に落ちる）。
3. モデルが陥りやすい既定値を名指しで禁じる：よくある書体（Arial・Inter 等）・紫のグラデーションと白地・同じ形のカードの並び・飾りだけの動き。
4. 色は CSS の変数で 1 つのテーマにまとめる。動きは、意味のある少数の場面に集中させる（CSS だけで足りるなら CSS）。
5. 先に「美的な方向」を 1 つ選んで言葉にし、それに最後まで従う（途中で混ぜない）。

## 型 2：Stitch の 4 部構成
[文脈と様式]＋[配置の構造]＋[部品の詳細]＋[内容とデータ]。長すぎる指示（約 5,000 字超）は部品が落ちるという報告があるので、まず全体を短く、次に画面ごとに足す。
スマホは、プラットフォームの作法（iOS か Android か）を明示しないと、ウェブ風の部品が混ざる、という報告がある。

## 型 3：デザイントークンを先に決める
実装の前に DESIGN.md（色・書体・字の大きさの段階・余白の段階・角の丸み・影・動きの長さと曲線）を書き、実装はその変数だけを使う。画面ごとにばらつくのを防ぐ。

## 型 4：自己点検の表（出す前に自分で採点）
階層（最初に目に入るのは何か）／余白と整列／色の役割（意味のある色だけ）／文字の可読性と日本語の行間／状態（空・読み込み・エラー・運賃不明・確からしさ）／タップ領域／ライトとダーク／320px／動きの控えめさ／「ありきたり」への逆戻りがないか。弱い所は直してから出す。

## この案件で固定する条件（全案共通）
- スマホ縦向き（基準 390×844、360×800、320×640）。安全領域、親指の届く下部の操作、タップ領域 44px 以上。
- UI の名前は名詞。文字より SVG のアイコン。絵文字なし。色だけに頼らない（文字・形でも示す）。
- 外部の CDN・外部フォント・外部通信なし（システムの書体で、書体の指定を工夫する）。
- Google マップはリンクアウトのみ。クラウドに保存するのは、お気に入りと設定だけ。履歴は端末の中だけ。
- ブランド名は「GyrotraffIC」（表記を崩さない）。
