# 新宿駅 3D マップ：完全に近づける段取り

いまの到達点：公的オープンデータからの下書き（`data/shinjuku/shinjuku-station.json`）。全要素が「推」で、現地確認は 0 件。詳しくは COVERAGE.md。

## 段取り

1. **データ**（済み／一部）
   - 済み：東京都 CC BY データ（ネットワーク・施設）、国交省データの出口、OSM の件数照合。
   - 次：国交省データを、G空間情報センターでユーザ登録してから取り直す（人）。ODPT は利用登録してから、駅施設データの項目（座標・階・改札の内外）を仕様書で確かめる（人がキーを取る）。
   - 済み（2026-10-19）：東京都と国交省の施設を、同じ階・同じ種類・5 m 以内で突き合わせた（CROSSCHECK.md、一致 344・食い違い 108）。ネットワークの切れ目を原因別に分け、一部を推測の接続で直した（COVERAGE.md）。
   - 次：現地確認（FIELD-CHECKLIST.md、ホーム階とエレベーターから）。国交省への権利の確認（MLIT-INQUIRY-DRAFT.md、送るのは人）。
2. **モデル**
   - 階の高さを決める（いまは 5 m 刻みの仮置き）。資料がなければ「不明」のまま残し、見た目だけ仮の高さで描く。
   - 名前のないホーム 18 区画と線路の位置を埋める（資料が得られた分だけ）。作り話では埋めない。
   - 出口と通路のつながり（いまは最寄りの点へ直線）を、現地で確かめたものから置き換える。
3. **3D の検証**
   - ui-variants/e-station3d のビューアで読み込めるか確かめる（今回は別の担当が作業中なので走らせていない）。キーは見本と同じだが、`platforms` の号車・ドアなどは null。ビューアが null に対応しているかは不明。
   - 確かめる点：階ごとに床が水平に分かれているか、階をまたぐ辺が階段・エスカレーター・エレベーターだけか、離れたネットワーク（いま 6 個。最大 2472 点、ほかは 89・61・4・4・2 点）のつながりが抜けていないか。
4. **現地確認**
   - 階ごと・施設の種類ごとに確認表を作る（ID・あるか・位置のずれ・名前）。確かめた物から `conf` を「確」にする。
   - 構内の撮影・測定は事業者の決まりに従う。必要なら事業者に許可を取る。

## 必要な人の作業

- G空間情報センターのユーザ登録と、データの取り直し。
- 国交省（高精度測位社会プロジェクト）への問い合わせ：元資料（事業者の構内図など）の権利処理が済んでいるか、アプリで公開してよいか。
- ODPT の利用登録（キーの取得）。
- 鉄道事業者・地下街への問い合わせ：階の高さ、号車とドアの位置、出口番号の体系。構内図を使いたいときは、その利用許諾も。
- 現地確認（階ごとに数時間ずつ、何回かに分けて）。
