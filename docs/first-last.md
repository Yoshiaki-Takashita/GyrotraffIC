# 始発・終電の探索（設計案）　2026-10-19

> 印：**確**＝コードで確かめた。**推**＝推論。**不明**＝確かめていない。実装はまだ（設計のみ）。

## 1. 問い
- **始発**：「運行日 D に、A から B へ、最も早く着ける経路」＝ D の運行開始以降でいちばん早い到着。単に「0 時に出発」で前向き探索すると、前日（D−1）の 24 時超えの便（終夜・深夜便）が答えになる（`Network.day` が D−1 の便を重ねるため。確）。始発の意味は「D の運行日の最初」なので、運行日の境界を問いに持たせる。
- **終電**：「運行日 D のうちに A を出て B に着ける、最も遅い出発」。到着の期限は「D の最終便が着くまで」で、時刻ではなく「その運行日の便だけを使う」という条件で決まる。24 時を超える便（25:10 など）も D の便として含む。

## 2. 中枢に足すもの
| 部品 | 内容 |
|---|---|
| `Router.earliest(q)`（始発） | 前向き RAPTOR。`Network.day(D)` の便のうち `dayOffset` が 0（と、設定で +1 を除く）の便だけに乗れる印を付けて走らせる。出発は D の「運行日の始まり」（既定 03:00 推。事業者の運行日の境界はデータに無いことが多い＝不明。設定で変える）。答えは乗り換え回数ごとのパレート集合（到着×乗り換え）。 |
| `Router.latest(q)`（終電） | **逆向き RAPTOR**（到着から時刻表を逆にたどり、各停留所の「間に合う最も遅い出発」を求める）。乗れる便は D の運行日の便だけ（`dayOffset`＝0）。目的地の期限は「無限大」から始め、各ラウンドで出発を最も遅くする。答えは（出発の遅さ×乗り換え）のパレート集合。今の `arriveBy`（二分探索）でも「期限＝D の 30:00」とすれば近似できるが、探索が (K+1)×約 10 回になり、運行日の制限も無い。 |
| 運行日の制限 | `PatternDay.dayOffset` は既にある（確）。走査のとき「乗る便の dayOffset が許す範囲か」を見る 1 行の条件を足すだけで、パターンの FIFO は崩れない（推：便の部分集合を取るだけで順番は変わらない。ただし二分探索で「最も早い便」を探す所は、許されない便を飛ばす必要がある）。 |
| 逆向きの網 | 逆向き RAPTOR は、パターンを後ろから走査し、徒歩も逆向き（b→a）に使う。`Network` に逆向きの徒歩の索引（`fpInStart`・`fpFrom`）を足す。前処理は 1 回、メモリは徒歩の本数ぶん（推）。 |

## 3. 来歴と不明
- 始発・終電の答えには「この運行日の時刻表で計算」「特別ダイヤ（年末年始・臨時）未反映の場合あり」を付ける（CD 6）。祝日の展開が無いフィードでは、土休日の判定が「不明」になりうるので、運行日の判定に確信度（calendar_dates の明示＝確、曜日からの判定＝推、祝日の展開なし＝推）を持たせる。
- 「運行日の始まり」の既定値（03:00）は推。データ源に境界が書かれていれば確に上げる。
- 終電の後の「翌日の始発」を同じ画面に出すときは、別の問い（D+1 の始発）として探し、混ぜない。

## 4. 試験の案
1. 24 時超えの便があるとき、始発の答えに前日の深夜便が入らない。
2. 終電：答えの出発を 1 分遅らせると、同じ運行日では着けない（今の `arriveBy` の試験と同じ考え方）。
3. 逆向き RAPTOR と、二分探索版（期限を十分遅くした `arriveBy`）の出発時刻が、合成網の無作為な問いで一致（CD 9 の性質⑥）。
4. 運行日の制限で FIFO が崩れない（無作為網で、制限あり・なしの答えの包含関係）。
