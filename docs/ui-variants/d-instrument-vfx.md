# 案 D「計器」VFX（d-instrument-vfx）

**結論**：案 D「計器」の見た目（暗い面・青緑の 1 色の発光・細い線・等幅の数字）はそのままに、押す・拒否する・長押しする・入れ替える・並べ替える・運ぶ・払う・画面を移る、の動きを、自作のばねの基盤（依存ゼロ）で作り直した。震えは「UI が震えて見える動き」を主役にし、触覚の振動は添え物（無くても成立）。既存の検査はすべて合格（3 幅 × ライト／ダーク・コンソールエラー 0・外部通信 0・横スクロールなし・タップ 44px 以上）。コンタクトシートで 4 回見て直した。動きの自己点検は全項目 4 以上（自己採点）。**実機のスマホでは確認していない**（手触り・振動・電池は不明）。

## 要約（非エンジニア向け）
1. 見た目は案 D のまま。変えたのは「動き」だけです。
2. ボタンは押すとわずかに沈み、離すとばねのように戻って小さく揺れます。
3. 「検索」を押すと、押した点から光が広がり、ボタンの小さなランプが点きます。
4. 出発地と目的地が同じなど、受け付けられない操作は、入力欄が首を振るように震えて止まります（約 0.34 秒）。
5. 「経路の保存」は長押し。押している間に輪が満ち、張りつめるように震え、満ちた瞬間に輪が弾けます。
6. 入れ替えボタンで、2 つの地名が弧を描いてすれ違います（片方は奥を通る）。
7. 保存した経路は、つまみを持って並べ替えられます。ほかの行がばねで道を開けます。
8. 結果の案を長押しして下の「保存」タブへ運ぶと、タブが光って膨らみ、案が吸い込まれて保存されます。
9. 結果→詳細では、選んだ案の経路の線が、そのまま詳細の線へ移ります。詳細は下に払うと閉じます。
10. 待機中は何も動きません（電池を使わない）。「動きを減らす」設定では、震えや移動の代わりに色と形で伝えます。

## 作った動き（何を・なぜ・どう）
| 動き | 狙い（意味） | どう動くか |
|---|---|---|
| 押す（全ボタン） | 押したことが指の下ですぐ分かる | pointerdown の同じコマで沈み始める（臨界減衰 k900）。離すと弱減衰（k520・ζ0.42）で戻り、沈んだ量に比例した初速で小さく行き過ぎる。大きなボタンは戻った後に縦 1px 未満の減衰振動 |
| 主操作（検索） | 「始動」の因果 | 押した点から光の円が広がる（420ms・transform と opacity）。右端のランプが点灯し、ばねで定まる |
| 拒否の震え | 「受け付けない」をことばより先に | 9Hz を基本に 3 つの周波数の合成＋微小な位相の乱れ。振幅 10px が時定数約 80ms で減衰し 340ms で必ず静止。ごくわずかな回転を足す。縁が危険色になる（動きを減らす設定ではこれだけ） |
| 長押し（保存） | 誤操作を防ぎ、確定の手応え | 輪が時間に比例して満ちる（560ms）。満ちるほど震えが強まる（0.2→2px）。確定で震えは一気に消え、拡がる輪・沈み込み・アイコンの脈。途中で離すと輪はばねで戻る。短いタップは「長押しで保存」の案内。キーボードは即時 |
| 入れ替え | 2 つの値が「交換された」ことを空間で | 出発地の文字は手前を右へふくらむ弧、目的地の文字は奥（小さく・薄く）を通る。速度に応じて縦に伸びる。途中で押し直すと、今の位置と速度から戻る（中断可能） |
| 並べ替え | 持ち上げ→道を開ける→収まる | つまむと 1.03 倍＋発光の縁（影は使わない）。端はゴムの抵抗。ほかの行は k420 で道を開ける。離した速度を引き継ぎ、行き過ぎ付きで収まる。上下の矢印キーでも 1 行ずつ（FLIP） |
| タブへ運ぶ | 「ここに置ける」の予告と因果 | タッチは 300ms の長押しで持ち上げ（それまではスクロールに譲る）、マウスは 8px 動かすと開始。指に少し遅れて付く（重さ）。速さに応じて細かく震え（引きずる抵抗）、タブに近づくほどタブが光り膨らむ。タブの上では両方が共鳴するように震える。離すと縮みながら弧を描いて吸い込まれ、タブのアイコンが脈打つ。途中で戻すと速度を引き継いで元へ |
| 払って閉じる | 物を下へ払う手触り | つまみと要約から下へ。上へはゴムの抵抗。離した速度から止まる位置を予測し、42% を超えるか 900px/s 以上なら閉じる、そうでなければばねで戻る。閉じたシートは不透明のまま下へ抜け、下の画面が奥から定まる |
| 結果→詳細 | 「この案の詳細」という連続性 | 選んだ案のリボンが詳細のリボンの位置と幅へ移る（FLIP・k260 ζ0.86）。元のリボンは消える。ほかは所要時間→時刻→区分→目盛り→凡例→区間→操作の順に 34ms ずつ入る。戻るときは逆向きに詳細のリボンから一覧のリボンへ |
| タブの切り替え | 左右の位置関係 | 次のタブは右から 56px、戻るは左から。古い画面は速く薄れる。下部の指示線が前の位置と速度からばねで移る。背景の目盛りが逆向きに 10px ほどずれて戻る（視差） |
| 戻る・中断 | 逆再生ではなく、今の勢いから | 移りの途中で元の画面へ戻ると、作り直さずに、2 枚の画面の位置と速度を入れ替えて向きを変える |
| 起動 | 名前の「ジャイロ」を最初の 1 秒で | 傾いた水平線が弱減衰で水平に定まり（針の揺れ）、目盛りが中央から点灯。440ms で水平線が上部の境界線へ移り（View Transitions があれば使い、なければ自前の FLIP。同じばねを CSS の linear() に写して揃えた）、中身が段差で入る。約 0.85 秒で終わる |
| 計器 | 「探している→定まった」 | 姿勢計は今の角度と推定の角速度から弱減衰で水平へ、定まる直前に微細な回転の震え。カウンターは桁ごとに 60ms ずらし、上の桁ほど重いばねで回り、最後に 1px 未満の縦の震え |
| 光の脈・粒 | 経路の「到着」 | リボンを描き終えたら 1 回だけ光が走り、到着の節で小さな光の粒（40px の Canvas の中・最大 10 個・0.5 秒）。常時の動きはない |
| 選択の点灯 | ラジオ・タブの「今どれか」 | 選択の面がばねで移り、進む向きにわずかに伸びる。点が 0.2 倍から灯る |

## モーション基盤の使い方（`GT.M`）
```js
var mv = GT.M.el(el);                 // 要素ごとの動き（x, y, s, sx, sy, r, o のばね）
mv.to({ x: 120, o: 1 }, "page");      // 途中で呼び直しても速度を引き継ぐ。Promise は止まったとき
mv.to({ s: 1 }, { k: 520, zeta: 0.42 }, { s: 3 });   // 剛性・減衰比・初速
GT.M.spring({ from: 0, to: 1, spring: "wobble", onUpdate: function (x, v) {} });
GT.M.tremor(el, { amp: 2, freq: 13, dir: "xy", decay: 0.08 });   // 震え（時間ベース・必ず静止・同時 2 つまで）
GT.M.shake(el);                       // 拒否の震え
GT.M.flipFrom(el, firstRect);         // FLIP
GT.M.drag(el, { hold: 300, onStart, onMove, onEnd });   // Pointer Events＋捕捉・速度・慣性
GT.M.rubber(x, d); GT.M.project(v); GT.M.snap(pos, v, points);
GT.M.tween({ dur: 300, ease: "outCubic", onUpdate: function (p) {} }); GT.M.stagger(els, 40, fn);
GT.M.haptic("confirm");               // 対応端末だけ（添え物）
```
- ばねは半陰的オイラーを 1/240 秒の小刻みで積分し、1 コマの上限は 1/30 秒（タブ復帰などで暴れない）。減衰比 ζ で臨界（1）・過減衰（>1）・弱減衰（<1）を選ぶ。プリセットは `GT.M.SPRING`
- requestAnimationFrame は動いているものがある間だけ回す（待機中 1 秒のループ回数＝0 を検査で確認）
- 品質の自動調整：直近 40 コマの間隔の中央値が 19ms 超で段 1、28ms 超で段 0。段 0 は粒子なし・発光なし・同時に動かす要素 6 まで（通常 24）。`GT.M.q.force(0)` で確認
- 動きを減らす設定：`to()` は即時に最終値、震えは出さない。代わりに色と形（拒否＝縁の危険色、入れ替え＝ボタンの縁の点灯）
- 検査用：`GT.M.manual(true)` と `GT.M.advance(ms)` でコマ送り（コンタクトシートはこれで撮る）

## 正直な限界
- **実機の手触りは未確認**。ばねの値はヘッドレスのコマ送りと録画で決めた。指の速さ・画面の大きさで印象は変わる
- 触覚の振動は `navigator.vibrate` がある端末（Android の Chrome など）だけ。**iPhone の Safari では振動は出ない**（設計上、見た目だけで成立させている）
- タッチでの「長押しで持ち上げ」は、スクロールとの取り合いを touchmove の抑止で処理している。iOS Safari での挙動は未確認
- 長押しの保存は、タップだけでは保存されない（案内が出る）。慣れるまで戸惑う可能性
- 古い端末：品質の段は自動で下がるが、段が下がるまでの最初の 40 コマはそのままの質で動く。発光（box-shadow）自体は動かしていないが、ダークで多用している
- 読み上げ（VoiceOver・TalkBack）：動きは読み上げに影響しない作りだが、並べ替え・運ぶ操作の読み上げでの使い勝手（つまみの説明・矢印キー以外の代替）は未確認。運ぶ操作は詳細の長押し保存で代替できる
- コンタクトシートは基盤の時計を止めて撮るため、ブラウザの CSS のトランジション（タブの光など一部）は進み方が実時間と少しずれることがある。起動のシートは View Transitions を使わない側（自前の FLIP）。動画は実際の経路
- 結果の画面の「探索中」の最短待ち 0.56 秒は元の案と同じ（サンプルのときだけ）。詳細から戻るときは待たない
