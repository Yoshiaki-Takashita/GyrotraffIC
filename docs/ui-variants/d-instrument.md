# 案 D「計器」（d-instrument）

**結論**：暗い面に、少数の「計器」（大きな等幅の数字・細い目盛り・1 本の経路のリボン・小さな姿勢計）だけが青緑に光る、静かな案。機能は基本の UI と同じ（検索→結果→詳細→保存→設定）。自動検査はすべて合格（3 幅 × ライト／ダーク・コンソールエラー 0・横スクロールなし・タップ 44px 以上・コントラスト AA）。実機での確認は未実施。

## 要約（非エンジニア向け）
1. 飛行機の計器盤のような、暗くて静かな画面です（ライトも用意）。
2. 色は「暗い面＋青緑の 1 色」だけ。注意（推定・運賃不明）は琥珀色と形で示します。
3. 結果の画面では、小さな姿勢計が探している間だけ静かに揺れ、結果が出ると水平に定まります。
4. 同時に、最速の所要時間が機械式のカウンターのように桁ごとに回って止まります。
5. 詳細の画面では、経路が 1 本の線として伸び、乗り換えの駅が順に点灯します。線の長さは時間の比です。
6. 起動時は 0.9 秒だけ、水平線が定まる演出が出ます（1 回だけ）。
7. 一覧はカードを並べず、細い線で区切った行にしました。
8. 「動きを減らす」設定の端末では、動きはなく、止まった計器として表示します。
9. この環境では動きはほぼ毎秒 60 コマで滑らかでした（実機の値は不明）。
10. 弱点：暗い画面が好みに合わない人がいること、情報の密度が基本の UI より少し低いこと。

## 場所
- 画面：`ui-variants/d-instrument/index.html`（ファイルを直接開けば動く。外部通信なし）
- 設計の変数：`ui-variants/d-instrument/DESIGN.md`
- 部品：`ui-variants/d-instrument/js/instrument.js`（姿勢計・カウンター・リボン・起動の演出・時計）
- 検査：`NODE_PATH=/opt/node-tools/node_modules node ui-variants/d-instrument/tests/check.mjs --round=final`
- スクリーンショット：`docs/ui-variants/d-instrument/final/`（最終）、`before/`（第 1 回の直す前）

## 案の方向と理由
名前 GyrotraffIC の gyro（姿勢計）・traffic（経路）・IC（精密な部品）から、航空機の計器盤を選んだ。計器盤は「必要な値だけを、大きく・正確に」見せる道具なので、所有者の方針「洗練された、シンプル・引き算」と一致する。飾りは意味のある目盛り（姿勢計の傾きの目盛り、リボンの下の 10 分ごとの目盛り）だけ。

## 見せ場（3 場面＋起動）
| 画面 | 見せ場 | 狙い |
|---|---|---|
| 起動 | 傾いた水平線が定まる（0.9 秒・1 回だけ） | 名前の「ジャイロ」を最初の 1 秒で伝える |
| 結果 | 姿勢計が検索中だけ揺れ、結果で今の傾きから水平へ定まる（途中の角度から滑らかにつなぐ）＋最速の所要時間のカウンター | 「探している→決まった」を 1 つの動きで見せる |
| 詳細 | 経路のリボンが左から伸び、乗り換えの節が時間の比の順に点灯 | 経路の全体の形を、読む前に一目で |

注：サンプルのデータ層は即座に返るので、姿勢計が読み取れるよう、結果の表示を最短 0.56 秒待たせている（動きを減らす設定では待たない）。本物の探索ではこの待ちは探索時間に吸収される想定。

## 検証（この環境での結果）
- コンソールエラー 0、外部通信 0、横スクロールなし、タップ 44px 以上、ラベル、コントラスト AA：390×844・360×800・320×640 × ライト／ダークで合格
- 画面遷移の通し（検索→結果→並び替え→詳細→保存→保存一覧→設定→履歴の消去）、PC の中央の枠、保存が使えない環境：合格
- 動きを減らす設定：起動の演出なし・姿勢計は静止・カウンターは最終値・リボンは最初から点灯（自動で確認）
- 起動の演出は約 1 秒で消える（自動で確認）
- フレーム速度（requestAnimationFrame の間隔・ヘッドレス Chromium・この環境の参考値）：
  - 結果（姿勢計＋カウンター・1.8 秒）：平均 60.0fps、最悪 16.8ms、33ms 超 0
  - 詳細（リボン・1.2 秒）：平均 59.2fps、最悪 33.3ms、33ms 超 0〜1（回によって違う）
  - 起動の演出：平均 58〜59fps、最悪 50ms（読み込み直後の 1 コマ）
  - 実機（特に古い Android）での値は**不明**

## 長所と短所（正直に）
長所
- 名前と見た目が一致していて、他の案と区別しやすい
- 見せ場が 3 つ＋起動に絞られ、すべて transform／opacity だけで軽い
- 数字が等幅で、時刻の比較がしやすい。リボンで経路の形が一目で分かる
短所
- 暗い画面が主なので、昼の屋外での見やすさは基本の UI に劣る可能性（ライトに切り替えは可能）
- 区画の見出しが 11px で小さい。高齢の利用者には大きい文字の設定が必要かもしれない
- リボンは短い区間（乗り換えの待ち）を最小 10px に広げるので、厳密な時間の比ではない
- 結果の表示を最短 0.56 秒待たせている（サンプルのときだけの演出上の待ち）
- 書体は端末の標準に頼るので、Android では印象が変わる（未確認）

## 実機での確認が必要なこと
- iPhone・Android の実機でのフレーム速度と電池への影響（特に姿勢計の揺れ・リボン）
- 安全領域（ノッチ・ホームバー）の見え方
- 屋外の明るさでのダークの見やすさ、ライトの発光なしの印象
- Android の標準書体（Roboto・Noto Sans JP）での数字と日本語の組み合わせ
- 画面の読み上げ（VoiceOver・TalkBack）での、カウンターとリボンの読み上げ
