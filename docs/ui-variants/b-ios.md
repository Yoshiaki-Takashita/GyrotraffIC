# UI 別案 B「iOS ネイティブ」（b-ios）

## 結論
iPhone の標準アプリと同じ作法（大きな見出し・グループ化された行・下から出るシート・下部のタブ）で作り直した別案を `ui-variants/b-ios/` に置いた。機能は基本の UI と同じ（検索→結果→詳細→保存→設定）。自動の通し検査（3 画面サイズ × ライト／ダーク＋動きを減らす設定）は全部通った。自己点検の最終の平均は **4.4 / 5**。実機の iPhone では未確認。

## 非エンジニア向けの要約（10 行以内）
1. iPhone をふだん使う人が「説明なしで使える」ことを最優先にした案。
2. 画面は静か。色は青 1 色と、路線の色（線とアイコンだけ）。
3. 見せ場は 4 つだけ：詳細のシートの手触り、経路の線が伸びる、時刻の数字が流れる、押した行の時刻がシートの見出しへ移る。
4. 詳細は結果の上に下から出る。指でつかんで半分・全体・閉じるを選べる。
5. 確からしさ（確・推・不明）や運賃不明は、色だけでなく形と文字でも示す。
6. 動きを減らす設定の人には、動きをすべて止めて同じ情報を出す。
7. 外部の通信・フォントは使わない。Google マップはリンクだけ。
8. 弱点：Android の人には「iPhone 風」に見える。独自の個性は弱い。
9. 実機（iPhone の Safari・ホーム画面のアプリ）での手触りの確認が必要。

## 案の方向と理由
- 方向：Apple の Human Interface Guidelines に忠実（詳細は `ui-variants/b-ios/DESIGN.md`）。ウェブ風の部品・Android 風の部品（浮かぶ丸いボタン・下線のタブ・波紋）は混ぜない。
- 理由：所有者の方針「洗練・シンプル・引き算」と、iPhone の作法は相性が良い。そこそこの頻度で使うアプリは、使い方を思い出す手間が少ないほど良い。作法に寄せることで、見せ場（動き）の精度に手間を集中できる。
- 半透明のぼかしは、上のバー（スクロール後）・下のタブ・トーストだけ。本文の上には使わない（読みやすさ優先）。
- 書体はシステムの書体（iPhone では SF＋ヒラギノ角ゴ）。数字は等幅数字。

## 使った見せ場と狙い（1 画面に 1 つ）
| 場面 | 画面 | 中身 | 狙い |
|---|---|---|---|
| 1. シートの物理的な動き | 結果→詳細 | ばね（硬さ 420・減衰 38）。止まる高さは中間（画面の 60%）と大。離した速さを 0.2 秒ぶん先読みして行き先を決める。上端の先はゴムのような抵抗。下に払うと閉じて結果へ戻る | 標準のアプリと同じ「指に吸い付く」感触。ここが雑だと全体が安っぽく見えるため、最も精度を上げた |
| 2. 経路の線が描かれる | 詳細（シートの上部） | 区間の長さを所要時間に比例させた線が 520ms で左から伸び、駅の点が線の到達の瞬間に点灯。待ち時間は薄い破線 | 「飛行機まで 2 時間待つ」などが一目で分かる。飾りでなく情報 |
| 3. 時刻の数字が流れる | 結果 | 並び順（最速・乗換最少・安値）を変えると、行は動かず、時刻と所要時間の桁が縦に流れて入れ替わる（桁ごとに 22ms ずらし、わずかに行き過ぎて戻る） | 並べ替えで行が飛び回ると目で追えない。数字だけを変え、位置の記憶を保つ |
| 4. 共有要素 | 結果→詳細 | 押した行の「08:00 – 08:45」が、シートの見出しの位置まで 380ms で移る | 「どの案を開いたか」を目で確かめられる |

直した内容：
- R1 → R2：「今」なのに日時の行が出ていた（`hidden` が CSS に負けていた）／安値の注意書きが他の並び順でも出ていた（同じ原因）／入れ替えのボタンに区切り線が刺さっていた／乗り場の説明の折り返し／経路の線の待ち時間が空白に見えた → 薄い破線／詳細の 2 つのボタンが 2 行に折れた → 縦に並べた／ホームの題名を下部のタブと同じ「経路」に。

## 検証（この環境：ヘッドレス Chromium・playwright-core）
`NODE_PATH=/opt/node-tools/node_modules node ui-variants/b-ios/tests/check.mjs final`
- コンソールエラー 0、横スクロールなし、タップ 44px 未満 0（390×844・360×800・320×640 × ライト／ダーク）。
- 通し：入力 → 検索 → 並び順の変更 → 行を押す → シートが中間で止まる → 上に払って大 → 保存 → 下に払って閉じる → 結果に戻る → 保存 → 設定 → アカウント・出典。全部通過。
- 動きを減らす設定：シートは即座に中間の位置、共有要素の動きなし、経路の線は最初から描いた状態。
- フレーム速度（requestAnimationFrame の間隔の計測。この環境での参考値）：シート 60fps（最悪の 1 コマ 16.8ms）、経路の線 60fps（最悪 16.8ms）。**実機の値は不明。**
- 文字のコントラストは計算で確認（自動の検査には入れていない）。

## この案の長所と短所（正直に）
長所
- iPhone の人は覚えることがほぼない。戻る・閉じる・払う、がすべて標準の動き。
- 詳細が結果の上に出るので、案を比べ直すのが速い（閉じればすぐ結果）。
- 見せ場がすべて「情報を分かりやすくする」役目を持つ。

短所
- Android の人には他所の作法に見える（Android 版は別の作法で作る必要がある）。
- 個性・ブランドの印象は弱い。「GyrotraffIC らしさ」は経路の線くらい。
- ウェブで iOS を真似ているため、実機では本物の部品（標準の戻るの払い・慣性のスクロールとシートの連動）との細かな差が出るおそれ。特に、大きい高さのシートで本文を上端まで戻してから続けて下に引く動き（本文のスクロールからシートの移動への引き継ぎ）は未実装（つかみの部分では動く）。
- 大きな見出しの縮みは「バーに題名が出る」だけで、見出しそのものが滑らかに縮む動きは入れていない。

## 実機での確認が必要なこと
- iPhone の Safari／ホーム画面に追加したときの安全領域（上下）とぼかしの見え方。
- シートを指でつかんだときの手触り（ばねの硬さ・先読みの量）と、本文のスクロールとのぶつかり。
- 実機のフレーム速度（特に古い機種）。
- ヒラギノでの字の幅（この環境は Noto 系で撮影）。
- `datetime-local` の入力の見た目（iOS は独自の選択の画面）。
