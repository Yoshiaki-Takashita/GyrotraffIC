# 乗り場の精度：出入口・ホーム・バス停の向きの表し方　第 1 版・2026-10-19

> 印の意味：**[PROVEN]**＝一次資料で確認済み（URL を付記）。**[ARGUED]**＝根拠を示した推論。**[GUESS]**＝推測。**[UNKNOWN]**＝分かっていない。
> 前提：Google マップ等の画面やデータを抜き出すことは **しない**（`research-maps.md`）。位置は公開データ（GTFS-JP・ODPT・OSM・国土数値情報）と自前の実測から作り、外部の地図は **リンクで渡す** だけ。

## 要約（非エンジニア向け・10 行）
1. 「渋谷駅」ではなく「渋谷駅 銀座線ホーム」「A3 出口」「○○バス停 新宿方面の標柱」の単位で位置を持つ。
2. 位置には必ず **「どこから来たか」と「どれくらい正確か」** を付ける。正確さは A（±5 m）〜D（駅の代表点しか分からない）の 4 段階。
3. 正確さの段階で **見せ方を変える**。A・B は地図にピン、C は「この辺り」の円、D は駅名だけ出して「詳しい乗り場は不明」と正直に書く。
4. 出入口は OpenStreetMap（OSM）の「地下鉄出入口」の点が主な出どころ。番号（ref）と段差なし（wheelchair）も OSM にある [PROVEN]。
5. ホーム（番線）は時刻表データの乗り場 ID と OSM の `local_ref`（番線）を突き合わせる。合わなければ「番線不明」と出す。
6. バス停の向きは、標柱ごとのデータ（GTFS-JP）があればそれを使い、無ければ **その標柱を通る便の次の停留所の方角** から計算する（日本は左側通行なので道路の左側に標柱がある前提）。
7. 無い情報は推定で埋めず、Google マップ／Apple マップへの **リンク**で補う（リンクは無料・規約上も可、確認中）。
8. OSM 由来のデータは ODbL（改変したものは同じ条件で公開）の縛りがあるので、**自前で測った位置は OSM 由来と別の層に分けて持つ**。
9. 主要駅（まず 50 駅）は、所有者が現地で確かめる「実測」で A 段階に上げる。これがこのアプリの差別化点。
10. 利用者からの修正の受付は後の段階。受け付ける時は、提供された位置のライセンスを明確にする。

## 1. 何を表すか（データモデルは `core-design.md` 3 章と共通）

| 要素 | 単位 | 必須の属性 | 任意の属性 |
|---|---|---|---|
| Station（駅の束） | 駅・空港・港 | 名前、代表位置、種別 | 多言語名、読み |
| StopPoint（乗り場） | ホームの番線／バス停の標柱／桟橋／空港ターミナル | 位置、所属 Station、**向き**（バス停：方位角・道路の側）、**番線**（鉄道） | 階、乗車位置（号車）、屋根の有無 |
| Entrance（出入口） | 出入口 1 か所 | 位置、所属 Station、**出入口番号**（例 A3、西口） | 階、段差なし、エレベーター、開閉時刻、入口専用／出口専用 |
| Pathway（構内通路） | 出入口↔乗り場、乗り場↔乗り場 | 歩行秒（推定か実測か）、種別（通路・階段・エスカレーター・エレベーター・改札） | 幅、案内表示の文言 |
| Position（位置の来歴） | すべての位置に 1 つ | 出どころ、方法、精度（m）、確信度の段階、取得日、検証者 | 備考 |

- 「位置」は WGS84 の緯度経度＋階（`level`）。階は「地上 0・地下 −1」の整数か文字列（B2F）。GTFS の `levels.txt` の考え方に合わせる [PROVEN：GTFS 仕様（`review-architecture.md` の検証表）]。

## 3. 位置の確信度（Position の来歴）

### 3.1 属性
```
Position {
  lat, lon, level
  source:   "operator" | "gtfs" | "odpt" | "osm" | "ksj" | "survey" | "derived" | "manual"
  method:   "provided"       // データ源がその点として提供
          | "surveyed"       // 現地で実測
          | "matched"        // 複数データ源の一致で確定
          | "derived_trip"   // 便の次停留所から向きを計算
          | "centroid"       // 駅の代表点を流用
          | "estimated"      // 距離や名前からの推定
  accuracy_m: 推定の誤差半径（m）
  grade:    "A" | "B" | "C" | "D"
  observed_at, verified_by, source_version, license_id
}
```

### 3.2 段階と見せ方
| 段階 | 目安 | 典型の出どころ | 画面での扱い |
|---|---|---|---|
| **A** | ±5 m、階も分かる | 自前の実測、事業者提供で OSM と 10 m 以内で一致 | ピンと番号を出す。「A3 出口から徒歩 2 分」と言い切る |
| **B** | ±15 m | OSM の出入口・ホームの点（単独）、GTFS の `location_type=2` | ピンを出す。番号があれば出す |
| **C** | ±50 m | 便の経路から計算したバス停の向き、名前と距離の突き合わせだけで束ねた乗り場 | 「この辺り」の円。文言は「○○方面の乗り場（位置は目安）」 |
| **D** | 駅の代表点のみ | 乗り場・出入口のデータが無い | 駅名だけ。「出入口・ホームの詳しい位置は未整備」と明示し、外部地図へのリンクを出す |

- 段階は **低い方に倒す**：出どころの精度が不明なら C 以下にする [ARGUED：過大な精度表示は誤案内になる]。
- 複数のデータ源が **互いに 10 m 以内** [GUESS] で一致したら 1 段上げる（最大 A）。50 m 以上食い違ったら **両方 C に落として要確認の列に入れる**。

## 4. 出入口の作り方

1. OSM から `railway=subway_entrance`、`entrance=*`（鉄道駅の建物の入口）を抽出し、`stop_area` 関係か距離（例 150 m [GUESS]）で Station に結び付ける。
2. `ref` を出入口番号にする。無ければ `name`。両方無ければ「出入口（番号不明）」。
3. GTFS／ODPT に出入口があれば OSM と突き合わせ（名前・番号・距離）、一致したら A に近づける。
4. 出入口から乗り場への Pathway は、データがあればそれを、無ければ「出入口→駅の代表点→乗り場」の距離 × 係数 ＋ 階の差 × 固定秒（例 1 階あたり 30 秒 [GUESS]）で推定し `estimated` と印を付ける。
5. 利用者に出す「最寄りの出入口」は、目的地からの街路の徒歩が最短の出入口。**段階 D の駅では出入口を言わない**。

## 5. ホーム（番線）の作り方

1. 時刻表データの StopPoint に番線があれば（GTFS の `platform_code`、ODPT の列車時刻表の `odpt:platformNumber` [ARGUED：2 章の表]）それを正とする。ODPT では「駅 × 番線」の乗り場を列車時刻表から **逆算して作る**（駅情報そのものには番線の一覧が無いため）[ARGUED：`odpt:Station` の属性一覧に番線が無い]。
2. OSM の `public_transport=platform` の `local_ref` と突き合わせ、位置を得る。
3. 番線が時刻表側に無い場合は、**乗り場＝路線×方向** の粒度で止め、「番線不明」と出す。推測で番線を付けない [ARGUED]。
4. 同じホームを複数の路線が共用する場合（直通運転の典型）、StopPoint の等価関係（`core-design.md` 5.2）で結ぶ。根拠が弱い等価関係は張らない。
5. 列車の **乗車位置（号車）と出口の近さ**（「○両目が階段に近い」）は、データが無い限り出さない。将来の実測項目。

## 6. バス停の向き

1. GTFS-JP で標柱ごとに別の `stop_id` が付いていれば、それぞれを StopPoint にする。親停留所があれば Station に、無ければ名前と距離（例 100 m [GUESS]）で Station を作る。
2. 向きの決め方（優先順）：
   1. データに向き・方面の属性があればそれ [UNKNOWN：GTFS-JP の該当項目は検証中]。
   2. その標柱を通る便の **次の停留所**（複数あれば最頻のもの）への方位角を向きにする。`shapes.txt` があればその線上の最近傍点の進行方向。方法は `derived_trip`、段階 C。
   3. 日本は左側通行なので、進行方向に対して **道路の左側** に標柱があると仮定し、OSM の道路の中心線から左に 3〜5 m [GUESS] ずらした点を表示位置の候補にする（データの座標が道路の中心に置かれている場合の補正。元の座標が歩道側ならそのまま）。
3. 表示は「○○方面」（次の主要停留所名か `stop_headsign`）＋方位角から作った「北行き」等。**同名の反対側の標柱を同じ点に描かない**。
4. 同じ名前で 4 つ以上の標柱がある停留所（ターミナル）は、番号（のりば 1〜）があれば番号を優先する。

## 7. 足りない時の代替（フォールバック）

| 欠けている情報 | 代替 | 画面の文言 |
|---|---|---|
| 出入口 | 駅の代表点。外部地図へのリンク | 「出入口の位置は未整備。地図アプリで確認」 |
| 番線 | 路線×方向の乗り場 | 「番線は未確認」 |
| 構内の歩行時間 | 距離からの推定（`core-design.md` 4.5） | 「乗り換え 約 5 分（推定）」 |
| バス停の向き | 便の方角から計算（段階 C） | 「○○方面（位置は目安）」 |
| 駅そのものの座標 | 国土数値情報（鉄道駅）か OSM の `railway=station` [UNKNOWN：国土数値情報の利用条件は検証中] | — |
| 何も無い | 名前だけ。リンク | 「位置情報なし」 |

- 外部地図へのリンク：Google Maps URLs（検索・経路のリンク）、Apple の `maps.apple.com` のリンク。**リンクで渡すだけ**なら料金も保存制限も掛からないと理解している [UNKNOWN：Google Maps URLs の規約は検証中（`review-architecture.md`）]。リンクには「名前」か「丸めた座標」を入れ、自宅等の登録地点の座標は入れない（`accounts-privacy.md` T7）。

## 8. 実測（自前調査）の手順（段階 2 で主要 50 駅）

1. 対象：乗降客数と乗り換えの多さで上位の駅（例 新宿・渋谷・池袋・東京・品川・横浜…）[GUESS：順位は公開統計で決める]。
2. 1 駅あたり：出入口の位置（スマホの GPS は誤差 5〜10 m が普通なので、**建物の角・交差点など地図上で同定できる物との相対位置** で記録）、番号、階、段差、主要な構内の歩行時間（改札→各ホーム、ホーム↔ホーム）を歩測。
3. 記録は写真＋メモ＋緯度経度。入力は `survey`・`surveyed`・A 段階。検証者と日付を残す。
4. 事業者の構内図を **目で見て** 参照するのは可。ただし図そのものや図からの座標の転記を「事業者提供」として配布しない（著作権・利用条件の確認が要る）[ARGUED：安全側]。
5. 年 1 回、または工事の情報を得た時に再確認する。

## 9. ライセンス上の守り（詳細は `data-pipeline.md`）

- OSM 由来の点は ODbL。**改変・派生したデータベースを配布・公開利用する時は同じ ODbL で** [PROVEN：https://www.openstreetmap.org/copyright「If you alter or build upon our data, you may distribute the result only under the same license」]。
- 自前の実測・事業者提供・GTFS 由来の点は、OSM 由来の点と **別のテーブル（層）** に置き、画面で重ねる。こうすれば自前の層を ODbL にしないで済む可能性が高いが、「どこまでが派生データベースか」は法務の確認事項 [ARGUED → `accounts-privacy.md` Q10]。
- OSM の点を「検証に使っただけ」で自前の点の精度段階を上げた場合、その点が派生に当たるかは不明 [UNKNOWN → Q10]。それまでは **段階を上げる根拠に OSM を使った点は OSM 層として扱う**（安全側）。
- 画面には「© OpenStreetMap contributors」と ODbL のリンクを常に出す。

## 10. 検証

- **網羅率**：Station のうち出入口が 1 つ以上ある割合、ホームに番線がある割合、バス停に向きがある割合を、データ源ごとに毎回の取り込みで数える。目標（段階 2）：主要 50 駅は出入口 100%・A/B 段階、首都圏の地下鉄駅の出入口 80% 以上 [GUESS]。
- **整合**：同じ出入口を指す OSM と他データ源の距離の分布。50 m 以上の食い違いは一覧にして人が見る。
- **向きの正しさ**：無作為に 50 か所のバス停を選び、実際の方面と比べる。誤り 5% 以下 [GUESS]。
- **ゴールデン**：「渋谷 A3 出口→銀座線ホーム」など 20 組の歩行時間を実測し、推定との差を記録。推定の係数をそこから調整する。
